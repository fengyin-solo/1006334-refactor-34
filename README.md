# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 入廊作业审批口径（唯一实现）

入廊作业审批的状态判定收拢在 **`frontend/src/domain/entry-approval.ts`** 一处，
列表、确认批准/驳回/完工动作、CSV 导出都只读它，不再各算一遍。核心约定：

- **同一份校验**：申请编号（`ENTR-0001` 格式）、申请单位、作业舱室、安全措施的校验只在
  `validateDraft` 一处。
- **同一份推进关系**（`TRANSITIONS`），状态只由审批轨迹「最后一条带状态的事件」推导：
  - 提交审批：`待审批 / 已驳回 / 待补材料 → 待审批`（驳回允许补正重提）
  - 确认批准：`待审批 → 已批准`，同时在维保台账落一条 `WORK-xxxx` 工单
  - 驳回申请：`待审批 → 已驳回`
  - 登记完工：`已批准 → 已完工`，联动工单同步完工
- **导出列与字段不变**：仍是 `编号 + 8 个登记字段 + 当前状态`，但「当前状态/审批状态」与列表
  同源，杜绝「列表已驳回、导出已完工」。轨迹、缺项说明等内部字段不进导出。
- **安全措施为空**：不退回录入，而是收件挂成「待补材料」并给出说明；补齐后用同一编号重新提交，
  并入原记录，不会产生第二条。存量在途申请缺安全措施的，保持原结论（仍待审批），只加注记。
- **重复提交幂等**：同一申请编号永远一条记录；重复登记只在该条轨迹里追加留痕。
- **审批结论落维保台账**：批准即派单；同一动作连发多回，账上只一条工单，后几回并入该工单轨迹，
  不重复落账。
- **两条完工路径的先后与冲突兜底**：审批页「登记完工」与维保台账「确认完工」写的是同一条
  「完工」语义事件，先到者定状态、后到者并入轨迹；已完工/已驳回为终态冻结，后到路径不得覆盖。
  若工单先完工而申请尚未批准，台账不替审批下结论，只留痕说明。
- **归属控制**：申请按「责任班组」归属，仅本班组可写；非本班组在列表与台账入口均只读，
  越权提交/改动一律按归属驳回。顶栏可切换责任班组验证。
- **待办与台账同步**：看板「入廊作业待办」与维保台账在同一份数据上现算（`loadEntryTodos`），
  并自检「已批准申请 ⇄ 在途工单」一一对应；申请与工单的改动在一次事务里写回（`saveAll`）。
- **存量回填**：启动时幂等迁移一次——按提交日期（缺登记时刻的早期条目按序号排到 2021 年前
  各月月初）追加只读轨迹；在途申请结论不变、历史审批记录不改写；早年缺审批人员的按作业舱室
  推定值班岗位（电气/给排水/燃气/热力/综合，兜底「管廊运行值班岗」，统一标注「值班推定」）；
  已批准/已完工的历史结论补登维保台账，早期缺项（如完工日期）留空并在「缺项说明」注明缘由。

验证：`cd frontend && npm run verify:domain`（20 项场景断言，覆盖迁移、幂等、归属、两条完工
路径与冲突兜底）。
